Report a Bug or Request a Feature

Opening a GitHub issue is the fastest way to get something fixed or considered — it is public, it is searchable by the next person with the same problem, and it does not get lost in an inbox.

  • GitHub Issues — restless-forge (all tools live in one repository; mention the tool name in the issue title)

A good bug report is short but specific. The things that make a report actionable rather than a guessing game:

  • Which tool, and the page you were on.
  • Your browser and device — "Safari on an iPhone" is enough. A surprising share of bugs are specific to one browser.
  • What you expected versus what happened. These are different things and both are useful.
  • The file, if a file was involved — or at least its type and rough size. Since nothing is uploaded, I cannot see what you were working with unless you tell me.

That last point matters more here than on most sites: the tools process everything locally, so there are no server logs of your session to look at. Your description is genuinely the only evidence there is.
